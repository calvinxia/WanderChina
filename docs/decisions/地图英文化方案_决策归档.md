# 地图英文化方案 — 决策与待办归档

> **日期:** 2026-07-29
> **状态:** 方向已定,待眼前 Android 过审后排期执行
> **背景:** 高德 v10→v11 升级(为解决 16KB)后,原自定义地图样式失效,多轮修复失败并回滚。现改用高德原生英文底图,方向更优。

---

## 一句话结论

**放弃自定义样式路线,改用高德原生 `setMapLanguage(english)` 英文底图。** 这不是退而求其次,而是更优解——直接给外国游客英文地图,比"用自定义样式过滤中文"更彻底地达成了产品目的。一行代码替代整场样式苦战。

---

## 为什么转向(来龙去脉)

### 自定义样式为什么走进死路
- 为解决 Google Play 16KB 合规,高德 SDK 从 v10.1.200 升到 v11.2.000
- v11 改了渲染管线,原 v10 时代做的自定义样式(过滤无关中文信息)失效
- 排查排除了:ProGuard 混淆、shrinkResources、样式文件版本、加载时序
- 真正根因:`amap_map 1.0.15` 插件已于 2025-04 归档、绝版,其 Android 侧样式加载用的是 v10 的 `setStyleData(byte[])` API,与 v11 不兼容
- fork 插件尝试修复,不仅样式没救回来,还引入定位漂移 bug(定位飘到经纬度 0,0 / 非洲西海岸)→ 已回滚
- 结论:在绝版插件 + 强制 v11 的约束下,自定义样式是结构性死局,非改几行代码可解

### 为什么英文底图是更优解
- 自定义样式的**原始目的**只是:别让外国游客看到看不懂的中文
- `setMapLanguage(english)` 直接把底图地名、道路、POI 全变英文 —— 目的达成得更彻底
- 对"服务外国游客"的核心定位而言,英文底图 > 过滤中文的自定义样式
- **绕过了整个插件样式泥潭**,不必再救那个坏掉的样式

---

## 技术调查结论(已查实)

### 第 1 点:插件已原生暴露英文开关 ✅
`amap_map 1.0.15` 内置支持,无需 fork、无需平台通道:

```dart
// lib/src/types/ui.dart:26
enum MapLanguage {
  chinese('zh_cn'),
  english('en');
}
```

`AMapWidget` 构造器(amap_widget.dart:156)有 `mapLanguage` 参数,透传给原生 SDK。

**改法(一行):** `wander_map.dart:395` 的 `AMapWidget(...)` 加:
```dart
mapLanguage: MapLanguage.english,
```
目前没传此参数,默认中文。

> 高德底层 API:`setMapLanguage(String)`,`AMap.CHINESE` / `AMap.ENGLISH`,v5.5.0+ 支持,v11 一定有。

### 第 2 点:英文底图是栅格图(需真机实测观感)
- 官方明确:英文模式为栅格瓦片(非矢量),"效果需开发者根据应用场景实际评估"
- 预判:旅游场景常停在 zoom 15-17,栅格在此范围清晰度基本够;缩放时可能有瞬间模糊
- **必须真机实测,不能靠文档判断**

### 第 3 点:翻译覆盖层需重新定位
现有覆盖层是自定义 badge marker("英文大字 + 中文小字 + 有色背景框"),切英文底图后:

| 场景 | 结果 |
|---|---|
| 高知名度 POI(故宫、天坛)底图已有英文 | ⚠️ 双重英文标注,视觉嘈杂 |
| 小 POI(胡同小店)底图没有 | ✅ 覆盖层是唯一来源,有价值 |
| 覆盖层带中文副标题 | ✅ 互补:底图给英文,覆盖层给中英对照 |

**核心矛盾:** 高知名度 POI 会重叠嘈杂,小 POI 覆盖层仍有价值。切英文底图后覆盖层要从"给所有 POI 翻译"重新定位为"补充底图没有的 + 提供中英对照"。

## 执行步骤(过审后排期)

### 第一步(最关键):验证 english 底图单独效果
> ⚠️ 不要一上来测"样式与语言共存"——现有自定义样式本就不生效,共存与否无法观测,是无效验证。先测最简单的:english 单独行不行。

- `AMapWidget` 加 `mapLanguage: MapLanguage.english`
- 暂时关掉/不管自定义样式(反正不生效)
- **临时关掉翻译覆盖层 marker**,只看纯底图
- 真机观察并记录:
  - a. 地名、道路、POI 是否都变英文?
  - b. zoom 15-17 栅格清晰度可接受?
  - c. 缩放时的模糊/加载感可接受?
  - d. 英文 POI 覆盖够全,还是很多地方仍中文/空白?

**决策分支:**
- 效果好 → **彻底放弃自定义样式**,只用 english 底图,进入第二步
- 效果差(栅格糊 / POI 英文太少)→ 才重新考虑是否需要救回样式

### 第二步(第一步 OK 后):覆盖层配合
- 开回翻译覆盖层
- 找出"底图英文 + badge 英文"重叠的高知名度 POI
- 覆盖层重新定位,方向候选:
  - 高知名度 POI 不再叠 badge(底图够了)
  - 或 badge 保留但弱化:底图有英文的只显示中文对照,不重复英文
  - 只对底图未覆盖的小 POI 显示完整 badge

## 未来延展:覆盖层是多语言的唯一载体

> 详见 `多语言战略_第二曲线归档.md`。此处记录与地图直接相关的判断。

**关键认知:高德英文底图与 DeepSeek 覆盖层不是竞争关系,是不同天花板的两条路径。**

- **高德底图只有中/英两种**(`AMap.CHINESE` / `AMap.ENGLISH`),给不了第三语言 —— 这是高德的硬限制
- **覆盖层是语言无关的** —— 换个 target language 参数就能翻成法语、西语、日语

**推论:英文是唯一能"外包给高德"的语言,其他所有语言必须靠覆盖层。**

因此多语言架构下的分工:
- 英文用户 → 高德英文底图 + 覆盖层只补底图未收录的小 POI
- 非英文用户 → 覆盖层承担全部目标语言标注

### ⚠️ 对本次英文化的直接影响

本文档第二步规划的"覆盖层重新定位"(高知名度 POI 不再叠 badge、只补小 POI),是**英文场景下的当前形态,不是覆盖层的最终定位**。

**执行时务必注意:用配置/开关的方式弱化覆盖层,而不是删除其翻译能力。** 将来多语言启动时,这套覆盖层要能直接复用来承担非英语标注。

### 附带优势

项目发起人具备英/法/西/意把关能力 —— DeepSeek 初翻 + 人工校准可形成高质量 POI 译名库,是纯机器翻译竞品难以复制的沉淀资产。这让覆盖层的长期价值高于"英文阶段的补充标注"。
